# Tomato-Plugin · 观测枢图鉴

Yunzai-Bot（TRSS-Yunzai / Miao-Yunzai）图鉴插件。查询时实时读取米游社观测枢的数据，用 Yunzai 自带的渲染器出图，不需要下载图库，官方更新后这边自动跟上。

目前支持：原神。星铁的数据源已经预留（`model/obc.js` 里的 `ObcSource`），后续加一个 app 即可。

## 安装

在 Yunzai 根目录执行，然后重启 Yunzai：

```bash
git clone https://github.com/Tomato-0914/Tomato-Plugin.git ./plugins/Tomato-Plugin
```

之后发 `#更新图鉴` 即可在线更新。

从旧版 `plugins/obc-plugin` 迁移过来的：按上面的命令装好新的、删掉旧的 `plugins/obc-plugin`，再把旧文件夹里自己写的 `config/config.yaml`、`config/alias/`、`config/version/` 拷到新文件夹。缓存目录 `data/obc-plugin` 首次启动时会自动改名为 `data/Tomato-Plugin`，不用重建。

不需要额外装依赖：用到的 `yaml` 和渲染器都是 Yunzai 自带的。需要 Node.js 18 或更高版本（用到了内置 `fetch`）。

**建议安装 [喵喵插件](https://github.com/yoimiya-kokomi/miao-plugin)**（放在 `plugins/miao-plugin`）：命之座图标、武器立绘、圣遗物部件图、材料/掉落物图标，都是优先用喵喵插件本地的图，没有时才退回观测枢自己的图兜底，装了效果更好。角色展示图是反过来的：优先用观测枢自己的图（每个角色都有，覆盖最全，构图也更好看），没有时才退回喵喵插件的本地图兜底。整体上没装喵喵插件也能正常查询，只是部分图标效果会差一些。

## 指令

| 指令 | 说明 |
| --- | --- |
| `#护摩之杖图鉴` / `#图鉴护摩之杖` | 查询条目，支持别名和模糊匹配（`#雾切图鉴`）；角色（如 `#刻晴图鉴`）也支持，出专门的角色资料卡 |
| `护摩之杖图鉴` / `#护摩之杖` / `护摩之杖` | 不带 `#` 或不带“图鉴”也能查（`bareMatch`，默认开启）；只对武器、圣遗物、食物、敌人、秘境生效，且名称、别名或料理名完全对上时才回复，其余消息放行 |
| `#原石图鉴` / `#图鉴原石` | 道具等其他分类，以及苹果、鸟蛋、原石这类日常用词，只认这两种写法，避免闲聊误触和指令冲突 |
| `#武器图鉴` | 分类总览（合并转发）：各星级条数和对应指令；没有星级的分类（如背包）直接列出全部名称 |
| `#五星武器图鉴` / `#金色武器图鉴` / `#紫色圣遗物图鉴` | 该品质（金 紫 蓝 绿 白 = 五星到一星）的全部条目，按大版本分组（7.x、6.x…1.x，新版本在前），每行标注上线版本 |
| `#敌人图鉴` | 敌人没有品质（游戏里没有星级概念），直接按大版本分组 |
| `#背包图鉴` / `#养成道具图鉴` / `#金色贵重道具图鉴` | 背包按游戏背包页签（养成道具、材料、贵重道具、任务、小道具）分开，每个页签再按品质细分；观测枢更细的类型（如 `#角色天赋素材图鉴`、`#蒙德地区特产图鉴`）也能直接查 |
| `#图鉴分类` | 查看观测枢有哪些分类 |
| `#原神图鉴` / `#图鉴帮助` | 帮助（网页排版渲染成图，列出全部指令和当前配置；渲染失败时退回纯文字） |
| `#图鉴更新` | 重新拉取目录，顺带同步一次版本表（genshin-db），两边各自失败不互相影响（主人） |
| `#图鉴强制更新` | 清空详情缓存和图片缓存后同上（主人） |
| `#更新图鉴目录` | 只同步版本表，不刷新目录；`#图鉴更新` 已经包含这一步，一般不用单独发（主人） |
| `#图鉴清除缓存` | 清空全部详情缓存和图片缓存（主人） |
| `#图鉴清除缓存护摩之杖` | 只清这一条的详情缓存和图片缓存，下次查询时重新拉取、重新出图（主人） |
| `#图鉴清除图片缓存` / `#图鉴清除图片缓存兹白` | 只清图片缓存（全部 / 这一条），详情不重新拉，下次查询重新出图（主人） |
| `#图鉴调试护摩之杖` | 导出该条目的原始数据和结构摘要，并把原始数据文件直接发到聊天里（主人） |
| `#更新图鉴` / `#强制更新图鉴` | 从 git 远程更新插件并重启（主人，需 git clone 安装） |

武器条目会用专门的横版武器模板出图（名称、星级、类型、满级属性、技能、获取途径、全部升级材料、推荐角色）；角色条目用专门的角色资料卡出图，为了手机上看得清，拆成 3 张 800 宽的竖图、合并转发发出（不连发刷屏）：① 概览（称号、简介、立绘、基础资料、满级属性、突破材料合计、天赋升级材料合计、CV、特殊料理、名片）② 天赋（说明 + LV1/6/9/10/13 倍率表）③ 命之座 + 观测枢自己的推荐武器/圣遗物；不含任何第三方持有率统计，配色随角色主题色自动调整；食物、背包（道具）、敌人、秘境、圣遗物也有各自的横版卡片（圣遗物高度随内容变化），解析不出来时回退到通用长图；`#更新图鉴` 是升级插件本身，和 `#图鉴更新`（刷新目录数据+版本表）是两回事。

## 配置

`config/default.yaml` 是默认配置，升级时会被覆盖。要改的话新建 `config/config.yaml`，只写想覆盖的项，例如：

```yaml
priority: 50
renderScale: 150
```

改完配置不用重启（`priority` 除外）。装了[锅巴插件](https://github.com/guoba-yunzai/guoba-plugin)的话，也可以在锅巴面板里改常用项，保存后写入 `config/config.yaml`。

常用项：

- `priority`：默认 -100，比喵喵插件（未设置优先级，用 Yunzai 默认值）低得多，稳稳抢在逍遥、喵喵、Atlas 等插件前面接管“#xx图鉴”和条目名查询；查不到的消息照常交给它们。Atlas 自己的 `#图鉴升级`、`#图鉴插件升级` 不会被拦截。
- `bareMatch`：默认 `true`，`#堆高高`、`堆高高`、`堆高高图鉴` 都能查到；只有名称、别名或料理名完全对上才回复。关掉后只认带“图鉴”的指令。
- `bareCategories`：直接发名称能查的分类，默认 `[武器, 圣遗物, 食物, 敌人, 秘境]`；其余分类要发 `#名称图鉴`。
- `strictTitles`：日常用词或和其他插件指令重名的条目（苹果、鸟蛋、原石、摩拉等），只认 `#名称图鉴` / `#图鉴名称`；有别的撞名可以在 `config/config.yaml` 里重写这个列表（会整体替换默认列表，记得把默认的也抄上）。
- `skipCategories`：不响应的分类，默认空（都响应）；如果你还是想把某个分类交给别的插件处理（比如角色图鉴继续用喵喵插件），写 `skipCategories: [角色]` 即可。
- `render.imageProcess`：让米游社 CDN 先缩图再传，省带宽。图片显示不出来就设成 `''`。
- `render.excludeSections`：不想渲染的分段（默认跳过角色故事、配音/语音、关联词条）。
- `render.removeSelectors`：渲染前从正文里删掉的元素。
- `api.detailIdSplit` / `games.gs.newBase`：新旧数据源的分流阈值（默认 0，全部先走新接口）和新接口地址，一般不用动。
- 图片尺寸固定（武器图和卡片 1280×800，圣遗物卡片高度随内容变化，通用长图宽 760），想要更清晰调 `renderScale` 即可。
- `weapon.artDir`：喵喵插件的武器立绘目录。装了喵喵插件时优先用它的透明立绘，找不到（比如新武器喵喵还没更新）再用观测枢的图标。
- `artifact.artDir`：喵喵插件的圣遗物部件立绘目录，同样是装了喵喵插件时优先用透明图，找不到再用观测枢的图标（观测枢的圣遗物图标带个圆形底板，喵喵插件的是透明底）。
- `material.artDir`：喵喵插件的材料/掉落物图标目录（武器突破材料、地区特产、怪物掉落等），用在武器升级材料、敌人掉落物品、秘境可能掉落上；找不到（含食物加工材料，喵喵插件没有这个）时用观测枢的图标。
- `character.artDir`：喵喵插件的角色资源目录，用它的命之座图标，找不到时用观测枢自己的图兜底；角色展示图反过来，优先用观测枢自己的图（每个角色都有），没有时才退回这个目录里的抽卡展示图兜底。角色的展示图（不管是喵喵的还是观测枢的）都是整张不透明的图，不是抠图立绘，装在带边框的卡片里显示；观测枢的图构图不固定（常是大幅场景插画）完整显示不裁剪，喵喵的本地图统一是竖长半身像，裁剪铺满展示框。
- `renderScale`：图片渲染精度，50~300，默认 100；调到 150、200 图片更清晰，体积也更大。
- `renderTip`：生成前先回一句“正在生成”，嫌多可以关掉。
- `weapon.domainDays`：突破材料对应的秘境开放日，显示在“升级材料”标题后；新地区的材料在这里补上即可。

## 别名

自带别名在 `resources/alias/gs.yaml`，预置了 75 把五星武器和 112 把三、四星武器的简称与「角色专武」叫法（如 护摩、胡桃专武、匣里剑），以及 63 套圣遗物的简称和部件名（如 辰砂、魔女、月女的华彩 → 乐园遗落之花），均整理自 [miao-plugin](https://github.com/yoimiya-kokomi/miao-plugin) 的别名表（MIT License）。自己加的写到 `config/alias/gs.yaml`，格式相同，升级不会覆盖：

```yaml
雷电将军: [雷神, 将军]
苍白之火: ['#苍白']
```

别名前加 `#`（要带引号）就是弱别名：只在消息带 `#` 或“图鉴”时生效，`#苍白`、`苍白图鉴` 能查到苍白之火，单独发“苍白”不会触发。容易在闲聊里出现的简称都是弱别名，比如武器的 月光、雨伞、糟心、决斗、天光，圣遗物的 苍白、乐园、翠绿；圣遗物想不带 # 直接查可以发「苍白套」「乐园套」。

名称的一部分（比如“雾切”→ 雾切之回光）不用写，插件会自动模糊匹配。

食物的特色料理和奇怪 / 美味品质（比如「普茹斯蒂司」「奇怪的致水神」）在观测枢里没有单独的条目。插件启动后会在后台抓取会产出特色料理的食物，建立料理名索引（存在 `data/Tomato-Plugin/gs/dishes.json`），之后直接搜料理名，会出这道料理自己的卡片（自己的图、描述、效果和获得方式，并注明所属的原料理）。首次安装时索引要几分钟才能建完。

## 版本表

分类列表里的上线版本数据来自 [genshin-db](https://github.com/theBowja/genshin-db)（MIT License），观测枢本身不提供版本信息。武器、圣遗物、食物、敌人、背包（秘境因为 genshin-db 命名和观测枢对不上，暂时没收）各自的版本号，按优先级从低到高：

1. `resources/version/gs.yaml`：插件启动后自动在后台联网同步的数据，启动后 1 分钟内会先跑一次，之后每天固定时间（默认零点）检查一次 genshin-db 有没有更新，没变化就什么也不做；直连 GitHub 不通时会自动换 jsdelivr 镜像试一次；同步失败只记日志，不影响正常查询。这个文件是运行时生成的，不在 git 里（在 `.gitignore` 里排除了），不会跟 `#更新图鉴`/`#强制更新图鉴` 的 git 拉取冲突，也不会被插件升级覆盖掉，但也别手改——改了也会被下一次自动同步盖掉
2. `config/version/gs.yaml`：你自己补充或修正的，优先级最高，不会被自动同步覆盖

没有插件自带的底表随代码一起发布，装好后是空的，等第一次自动同步跑完（启动后 1 分钟以内）才有数据。这意味着刚装好、第一次同步完成之前，分类列表里的条目会先都显示在「未收录版本」组，之后自动补上；新版本刚上线、genshin-db 还没收录时同理。`#图鉴更新` 刷新目录时会顺带触发一次版本表同步，也可以单发 `#更新图鉴目录`（`#` 可以不带）只同步这一项，没有新内容会提示「没有从观测枢获取到新内容」。手动补充写到 `config/version/gs.yaml`：

```yaml
武器:
  某把新武器: '7.2'
```

## 缓存

都在 Yunzai 根目录的 `data/Tomato-Plugin/gs/` 下（目录名跟插件文件夹名一致）：

- `index.json`：目录，默认 6 小时刷新一次
- `detail/`：条目详情（新旧两套接口拉下来后都规范成同一结构存这里），默认 12 小时
- `Atlas/`：图片缓存，先按分类再按图鉴名分文件夹，如 `Atlas/角色/兹白/1.jpg、2.jpg、3.jpg` + `meta.json`、`Atlas/武器/护摩之杖/1.jpg`。分类用观测枢的分类名（角色、武器、圣遗物、食物、敌人、秘境…），背包道具按游戏背包页签（养成道具、材料、贵重道具、任务、小道具），特色料理跟着所属食物放在「食物」下

图片缓存默认开启（配置 `imageCache`，锅巴里也能开关）：第一次查询渲染出图后存下来，之后再查同一条直接发本地图，不拉数据也不渲染，角色卡这种 3 张图的尤其明显。缓存不会自动过期，觉得数据不对就发 `#图鉴清除缓存兹白`（连详情一起重新拉）或 `#图鉴清除图片缓存兹白`（只重新出图）；改了渲染精度、图片质量，或者插件更新改了模板/解析代码时，旧图会自动作废重新生成。关掉 `imageCache` 后每次都重新生成，已有的缓存文件不会被删。同一分类里重名的条目放在 `名称_条目id` 文件夹里，互不覆盖。

接口请求失败时会先用旧缓存顶上。插件升级后如果详情的解析结构变了，旧的详情缓存会自动重新拉取。

`#xx图鉴` 没有命中任何条目时不回复，交给其他插件处理；`#图鉴xx` 没命中时才会给出相近条目的提示。

## 数据源说明

观测枢的内容有两套接口：

- 新接口：`hoyowiki` 的 `entry_page`，正文是一套结构化模块。新旧条目（包括 id 小于 500000 的老条目）都能查到，数据也更全，比如敌人的生命值和抗性、秘境各难度的掉落和敌人图标。
- 旧接口：`blackboard` 的 `content/info`，正文是整段带 `obc-tmpl` 组件的 HTML。

插件默认所有条目先走新接口；新接口报“内容不存在”或没有模块数据时，自动退回旧接口。旧接口的解析全部保留，作为兜底。

## 已知情况

- 目录每次从接口刷新后会顺带补全特色料理索引，游戏更新后新料理不用重启也能搜到。
- 目录、详情、匹配、清洗链路都已连真实接口跑通，新旧条目都能正常查询。
- 观测枢正文是 HTML / 结构化模块，目前按通用规则清洗后统一渲染；分区查询（只看天赋、命座等）还没做——新版模块名（天赋、命之座）已经非常规整，做起来不难。
- 使用的是米游社非公开接口，随时可能变动；接口结构变了发 `#图鉴调试名称` 把结果反馈过来。
